# PhD Studio 设计文档（v2）

> 本地运行的 PhD 科研工作台。v1 是"开源缝合调研 + PRD"，v2 把 v1 的需求和后来对话里新增的需求合在一起，标出现状，并给出待建模块的设计。
> 状态：✅ 已实现并实测 · 🟡 部分实现 · ⬜ 未实现 · 🆕 v1 里没有、新增的需求

## 1. 定位与原则

- **数据只在本地。** Obsidian vault 和 Zotero 是唯一真相源。工作台主要做"读"，以及"一个顺手的 Claude 窗口"。
- **改 vault 要确认，例外很少。**
  - Claude 改任何笔记，都先给你看差异，你点"允许"才写入。
  - 例外一：阅读清单、规划、想法这类结构化数据。工作台直接写，但只写各自那一个 YAML 文件。
  - 例外二：划词摘录。只往论文笔记里追加一行，写入前你能看到这一行的原样，写完可一键撤销：这之后笔记没被改过就逐字节还原，改过就只删掉这一行。
    - 原地写入，文件的创建时间和换行风格（含 CRLF）不变；代码块里的 `##` 不算小节。
    - 摘录的原文会转义，PDF 里的 `<s>`、`<img …>`、`$` 不会变成 HTML 或公式。笔记渲染时也会去掉脚本、事件属性和 javascript: 链接。
- **界面极简。** 苹果/谷歌式风格，左侧导航，少文字、多数字和图，细节点开再看。
- **不悄悄换模型。** Claude 不可用就直接报错，不会偷偷改用别的模型。
- **两台 Mac 同步安全。** 状态按设备分开存。两边同时改的结构化数据会自动合并冲突。大文件不进同步。
- **开源但匿名。** 代码在公开仓库，所有个人信息只放在不进仓库的 `studio.toml`。

## 4. 待建模块设计

左侧导航：**总览 · 清单 · 时间线 · 想法 · 方向 · 追踪 · 论文库**（全部上线），下面放助手、关闭和设置。

### 4.1 总览（新的首页）
- **一排数字：**
  - 下一个截稿还剩几天，同时标出是哪个会、绑定了哪篇论文；
  - 本周 T1 数量；
  - 收件箱数量；
  - 未整理的 idea 数量；
  - 本周追踪到的新论文数量。
- **未来 90 天时间轴：**
  - 在一条横轴上标出三类点：顶会截稿、目标截稿、个人里程碑；
  - 今天是一条竖线；
  - 鼠标悬停看详情。
- **研究线状态卡：** 每条研究线一张卡，写着当前阶段、最近一个 Gate、Kill criteria 灯。

### 4.2 时间线：三类 deadline
- **顶会截稿：**
  - 数据来自 ccfddl/ccf-deadlines 开源数据，每天刷新一次，界面上标明来源；
  - 摘要和全文截止时间都从 AoE 换算成本地时区；
  - 显示 CCF / CORE 等级；
  - 只显示关注的会议，关注列表放在 `studio.toml`。
- **目标截稿：** 研究线 → 目标会议（含备选）；截稿日期自动取自顶会数据。
- **个人规划：**
  - 里程碑字段：日期、研究线、状态（待开始/进行中/完成/预警）、备注；
  - Gate 和 Kill criteria 也作为里程碑存。
- **存储：** 全部存在 vault 里的一个 YAML 文件（例如 `00 Atlas/plan.yaml`），沿用阅读清单的同步安全写法。
- **命令行：** `studio milestone add/done`，其他会话也能更新进度。

### 4.3 想法：idea 捕捉
- **随手记：**
  - 任何页面按 ⌘I 弹出一个输入框，一句话就能存；
  - 自动附上当时正在读的论文和页码；
  - 可选研究线标签。
- **收件箱：**
  - 想法按时间排列；
  - 可丢弃，丢弃的保留记录。
- **自由标签：**
  - 想法卡上直接加、删，回车添加，逗号分隔可一次加几个；去掉前面的 `#`，大小写不同算同一个，最长 30 字；
  - 标签栏列出所有标签和条数（条数跟随当前的状态、研究线筛选），点几个就同时带这几个；
  - 助手：`idea_add` 带 `tags`，`idea_update` 用 `tags_add` / `tags_remove`，`idea_list` 按 `tags` 过滤；命令行：`studio idea tag <id> +x -y`、`studio idea list --tag x`（可重复）。
- **合并：**
  - 想法页「合并…」选两条以上，挑留下哪条的文字、或自己改；新想法的标签是各条的并集，论文和页码取留下那条文字的来源，研究线取多数；
  - 原想法状态变成 `merged`，默认不显示（想法页「已合并」、`studio idea list --all`、`idea_list` 的 `include_merged` 可以看），不会删除；
  - 来源记录：合并后的想法带 `merged_from`（原 id）和 `merged_sources`（每条原想法合并时的快照：原文、论文、页码、来源、标签、时间）；原想法带 `merged_into` 和 `premerge_status`；
  - 恢复：原想法逐条恢复成合并前的状态（合并后的想法不再列它），或在合并后的想法上「全部拆开」（全部恢复并删除这条合并结果）；合并成功的提示里有「撤销」；
  - 已整理成笔记的想法不能合并；命令行 `studio idea merge <id>… [--text …]`、`studio idea restore <id>`，助手 `idea_merge`，`idea_update` 的 `restore`。
- **整理成正式笔记：**
  - 点"整理成 idea 笔记"，Claude 按 AGENTS.md 的 Idea 结构起草：问题、为什么是现在、技术核心、第一个实验、Kill criteria、下一步证据；
  - 经你确认后写入 `02 Ideas/`，并链接到相关论文。
- **存储：** `02 Ideas/ideas.yaml`（同步安全）。
- **命令行：** `studio idea "…" [--tag x]`，其他会话也能记想法、加标签、合并。

### 4.5 追踪：同行动态 + 捕捉面板（10/25 已实现）
- **领域 Top 10 学者：**
  - 名单：个人数据，存在 vault 的 `<lab_tracker>/scholars.yaml`（同步安全的 Store，带删除墓碑）；仓库只放通用示例 `scholars.example.yaml`。每条记录写明来源（`sources`）。页面「管理名单」可按姓名在 OpenAlex 搜索后加入、或移除。
  - 排名口径：Google Scholar 领域排名（RecSys 相关标签合并、按 Scholar 总引用；在已登录的浏览器里取，程序不抓 Scholar），排除合作大论文刷高引用的条目和已故学者，再要求 2024–26 年至少 3 篇 LLM/agent 推荐研究论文（OpenAlex + tracker 主题模型，研讨会/教程不算），取前 10。同一实验室的学者先都保留，卡片上标「同 lab」。Scholar 取不到时可退回 OpenAlex 主题内引用。
  - 和 48 个实验室重合的学者标「48 lab 内」，并可直接打开该 lab 笔记。
- **名单定期更新：** 默认每 30 天自动重算一次，也可点「立即更新」。
  - 候选人：Scholar 标签榜（多个写法合并去重）加上当前名单，按 Scholar 总被引排序。
  - 筛选：近 24 个月至少 3 篇领域论文。用 OpenAlex 核实，关键词和主题组都可配置，研讨会和教程不计。
  - 剔除：被引主要来自超大合作组或领域外论文的人（按数据判断），以及排除名单里的人。
  - 每个实验室只留被引最高的一人（默认开启，可在规则里关掉）；实验室取自名单记录或 Lab Tracker 笔记，查不到实验室的人不参与这一条。
  - Scholar 数据来源：
    - 桌面 App 的第二个窗口：用户登录一次后，逐页读取标签榜，每页间隔 5–9 秒。遇到登录或人机验证时，手动重算会弹出窗口让用户自己完成，自动重算则先跳过。
    - 其次用导入或之前抓到的快照。
    - 再不行退回 OpenAlex 被引，并标注来源。
  - 结果以建议形式出现：列出谁进、谁出及原因，确认后才写入名单。
  - 可以「固定」（永不自动移除，并且不占前 N 名额，排在排名名单之后）或「排除」（不再推荐）。
  - 每次重算都留记录，卡片上显示名次变化（▲/▼/新）。
  - 稳健性：
    - 找不到或同名对不上的人只跳过这一个，原因写在建议里；OpenAlex 整体不可用时整次重算停止，失败次数存在数据目录，自动重试按 6 小时、12 小时……最长 7 天退避。
    - 当天抓到的 Scholar 页面会缓存，重试时不重新抓取。
    - 自动重算只在一台电脑上跑：默认是第一次重算的那台，记在 vault 里，可改成本机。记录 id 带设备名，已应用的记录不会被覆盖。
    - 「应用」只执行建议里显示的进出，并按当时的固定和排除名单再核对一次；建议生成之后手动加入（或从另一台同步来）的人不受影响。
    - Scholar 窗口在抓取结束时销毁，主窗口关闭时一并关闭，App 能正常退出。
  - 规则纯函数在 `app/scholar_rank.py`，有单元测试。
- **活动数据：** OpenAlex 作者指标、`counts_by_year`、近 365 天论文（会议/期刊名、合作者、主题）+ arXiv 最近 50 篇预印本（过 RecSys/IR 领域门槛，挡同名）。缓存在 `DATA_DIR/scholars`，24 小时过期，后台抓取并显示进度；离线时用旧缓存并标「旧数据」。限速：OpenAlex 每 0.2 秒一次（可在 secrets 的 `openalex.env` 放 `OPENALEX_API_KEY` 提额），arXiv 每 3 秒一次。
- **相关性：** 主题标签和 A/B/C 与每周 tracker 同一套模型（`research_tracker/config/topics.json`）；"触及我的课题" 按 `scholars.yaml` 里每条研究线的关键词（`a + b` 表示同时出现），没写时取研究线笔记的标签。
- **图表：** 学者×月份热力图（单一蓝色色阶）、每月产出（触及课题 / 其他两色堆叠）、主题分布条、学者卡片的每年发表趋势线、实验室×巡检热力图、各方向活跃度。OpenAlex 只给年份的论文（记成 1 月 1 日）不计入月度图。
- **论文卡片：** arXiv 论文显示首页上半部分缩略图（按需下载 PDF 渲染，缓存在 `DATA_DIR/track-thumbs`）；没有 arXiv 的显示会议名占位；点开看摘要和作者；一键进收件箱（带课题 lines），没有 arXiv 的交给助手找。
- **本周雷达 / 实验室 / 关注：** 原有内容改成图表 + 卡片（见第 3 节）。
- **tracker 联动：** 工作台的关注（plan.yaml follows）导出到 tracker 目录的 `config/follows.json`（只在增删关注时和巡检前、且内容变了才写，避免两台电脑互相覆盖）；tracker.py 的 fetch 会加查这些关键词/学者，ingest 保留命中关注的论文（即使不属于已跟踪的 lab），周报表格里标出命中的关注。
- **立即巡检：** 后台按 tracker 的周流程跑 fetch → ingest → render → vault_audit（RUN = 本地今天，SINCE = 最近一次运行），显示阶段和抓取进度；子进程用项目 venv 的 Python（App 包里 `sys.executable` 是启动器本身）。同一时间只跑一个：运行期间持有一把子进程会继承的文件锁（App 重启后也有效），发现别的 tracker 进程（如每周定时任务）也不启动；App 退出时停止正在跑的步骤。跑完可一键「交给助手写分析」。
