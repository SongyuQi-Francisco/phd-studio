# PhD Studio 设计文档（v2）

> 本地运行的 PhD 科研工作台。v1 是"开源缝合调研 + PRD"，v2 把 v1 的需求和后来对话里新增的需求合在一起，标出现状，并给出待建模块的设计。
> 状态：✅ 已实现并实测 · 🟡 部分实现 · ⬜ 未实现 · 🆕 v1 里没有、新增的需求

## 1. 定位与原则

- **数据只在本地。** Obsidian vault 和 Zotero 是唯一真相源。工作台主要做"读"，以及"一个顺手的 Claude 窗口"。
- **改 vault 要确认，例外很少。**
  - Claude 改任何笔记，都先给你看差异，你点"允许"才写入。
  - 例外一：阅读清单、规划、想法这类结构化数据。工作台直接写，但只写各自那一个 YAML 文件。
  - 例外二：划词摘录。只往论文笔记里追加一行，写入前你能看到这一行的原样，写完可一键撤销：这之后笔记没被改过就逐字节还原，改过就只删掉这一行。
    - 原地写入，文件的创建时间和换行风格（含 CRLF）不变；代码块里的 `##` 不算小节。
    - 摘录的原文会转义，PDF 里的 `<s>`、`<img …>`、`$` 不会变成 HTML 或公式。笔记渲染时也会去掉脚本、事件属性和 javascript: 链接。
  - 例外三：Zotero 链接写回。论文加进 Zotero 后，只往笔记 front matter 第一行加一行 `zotero: zotero://select/library/items/<key>`。写入前给你看这一行（和 Claude 改笔记同样的差异卡片），你点"写入"才写。预览之后笔记被改过就不写，要重新确认；已经有别的 Zotero 链接的笔记不动。原地写入，同摘录。
- **界面极简。** 苹果/谷歌式风格，左侧导航，少文字、多数字和图，细节点开再看。
- **不悄悄换模型。** Claude 不可用就直接报错，不会偷偷改用别的模型。
- **两台 Mac 同步安全。** 状态按设备分开存。两边同时改的结构化数据会自动合并冲突。大文件不进同步。
- **开源但匿名。** 代码在公开仓库，所有个人信息只放在不进仓库的 `studio.toml`。

## 3. 已实现的模块

| 模块 | 功能 |
|---|---|
| 阅读清单 | 5 个数字卡（收件箱、T1 本周 n/5 和 待读 n/12 带进度条、在读、本周读完带 12 周走势），点卡片跳到对应分组。<br>可收起的图表：状态环形图（收件箱 / T1–T3 / 在读 / 读完）和每周进出柱状图（加入 vs 读完），都跟随研究线筛选。<br>每篇带首页缩略图（本地或已缓存的 PDF；没有 PDF 时显示纸张占位），角标显示 T1–T3、在读、读完评价。<br>状态流转：收件箱 → T1/T2/T3 → 在读（打开论文时自动）→ 读完（略读/精读 + 关键/有用/无关 + 一句话收获，Claude 可起草）。<br>稍后 / 不读两个出口；超过 3 周没处理的自动收起；折叠分组平滑展开；键盘分拣 1/2/3/S/X/D/J/K/↵，J/K 会把选中行滚进视野。 |
| 论文库 | ⌘K 搜索全部论文笔记，排序跟随阅读清单。 |
| 阅读器 | pdf.js 阅读器，带目录、查找、缩放。<br>划词：翻译 / 讲解 / 问 Claude / 摘录到笔记（带页码，可撤销）；⌥ 拖动框选截图提问。<br>原文 / 双语 / 中文切换；只有 arXiv 号、还没笔记的论文也能读。双语按钮显示后台状态：排队第几、生成中（计时），排着队时点它可以"现在就生成"。 |
| Claude 伴读 | 每篇论文一个持续会话，流式回答。<br>能读 vault、全文和网页；改笔记前先给你确认差异。<br>快捷指令：速读、讲解本页、和我的课题、更新/新建笔记、Claim Gate 审计。 |
| 笔记 | 看论文对应的 Obsidian 笔记，一键在 Obsidian 打开，让 Claude 更新；笔记里的页码、章节号点击跳到 PDF 对应位置。 |
| 推送命令 | 其他会话或脚本可调用：`studio push / list / done`。 |
| 桌面 App | 原子图标，原生窗口；关窗口或 ⌘Q 整体退出；重复双击只会把已有窗口调到前面。 |
| 设置 | Claude 连接状态、伴读模型、Zotero（桌面端 / 网络密钥状态、自动入库、放进哪个分类、待写回笔记的链接、怎么建网络密钥）、翻译引擎、预生成双语（关 / T1 / T1 + T2，一键切换，默认关）、双语队列、双语 PDF 占用与清理、截稿提醒（一行摘要，点开是单独的面板）。 |
| 截稿提醒 | 三个数字（30 天内提醒条数、下一条在几天后、后台检查状态）和 30 天提醒分布条；开关、提前量（预设 + 自定，0–90 天）、提醒哪几类、免打扰时段、提醒设备、安装/卸载后台检查、「发一条测试通知」；下面列出接下来的提醒。点通知回到工作台并打开对应会议或「我的规划」。 |

## 4. 待建模块设计

左侧导航：**总览 · 清单 · 时间线 · 想法 · 方向 · 追踪 · 论文库**（全部上线），下面放助手、关闭和设置。

### 4.1 总览（新的首页）
- **一排数字：**
  - 下一个截稿还剩几天，同时标出是哪个会、绑定了哪篇论文；
  - 本周 T1 数量；
  - 收件箱数量；
  - 未整理的 idea 数量；
  - 本周追踪到的新论文数量。
- **未来 90 天时间轴：**
  - 在一条横轴上标出三类点：顶会截稿、目标截稿、个人里程碑；
  - 今天是一条竖线；
  - 鼠标悬停看详情。
- **研究线状态卡：** 每条研究线一张卡，写着当前阶段、最近一个 Gate、Kill criteria 灯。

### 4.2 时间线：三类 deadline
- **顶会截稿：**
  - 数据来自 ccfddl/ccf-deadlines 开源数据，每天刷新一次，界面上标明来源；
  - 摘要和全文截止时间都从 AoE 换算成本地时区；
  - 显示 CCF / CORE 等级；
  - 只显示关注的会议，关注列表放在 `studio.toml`。
- **目标截稿：** 研究线 → 目标会议（含备选）；截稿日期自动取自顶会数据。
- **个人规划：**
  - 里程碑字段：日期、研究线、状态（待开始/进行中/完成/预警）、备注；
  - Gate 和 Kill criteria 也作为里程碑存。
- **存储：** 全部存在 vault 里的一个 YAML 文件（例如 `00 Atlas/plan.yaml`），沿用阅读清单的同步安全写法。
- **命令行：** `studio milestone add/done`，其他会话也能更新进度。
- **会议信息过期提醒与核对（10/25）：** 赛道、页数、审稿规则是人工从官网核对写进 `data/venue_details.json` 的，会过期。
  - **新鲜度数据：** 每个会议记录 `edition_year`（详情描述的是哪一届）和 `verified_at`（哪天核对的）。
  - **三条规则，任一成立就显示「信息可能过期」并写明原因：**
    1. 届次：详情的届次早于 ccfddl 的「当前届」（最早一个还有截稿日期的届；都过了就取列出的最新一届），或没有记录届次。
    2. 时间：`verified_at` 距今满 N 个月（`studio.toml` 的 `[venues] stale_months`，默认 6），或没有核对日期。
    3. ccfddl：对详情所属那一届，ccfddl 给出详情里没有的链接，或详情里没有的截稿日期。链接去掉 `www`、末尾斜杠后比较，是详情里某个网址的上级也算已知；截稿时间相差 36 小时内算同一个（AoE / UTC / PT 写法不同），30 天前的旧日期不比。
  - **确认过一次核对后只看变化：** 确认写入或点「我已核对，没变化」时，记下当时 ccfddl 对详情所属那一届、以及对每个更新的届给出的链接和截稿日期，还有当前届（覆盖记录里的 `ccfddl_seen`）。之后只有相比那时的变化才再提醒：已经看过的差异、还只有占位页的新一届不会一直亮着；但这个占位的新一届后来有了链接或截稿日期（TBD 变成真日期），会再次提醒「有新一届」。
  - **让助手核对：** 详情页按钮把 `venue_check.check_prompt()` 生成的任务交给工作台助手（含现有链接、触发原因、步骤），助手读官网后调用 `venue_details_propose(venue, details, sources, summary)`。`details` 只写有变化的字段（可改的字段见工具说明；核对日期不能改，由系统写），`sources` 必填且必须是网址。工具只把提案存到 `state/<设备>/venue_proposals.json`（每个会议最多一条，不同步），不改任何数据；`venue_search` 也会带上 `freshness`。
  - **确认写入：** 详情页显示提案相对当前内容的差异和来源，点「确认写入」（`POST /api/venue-check/<key>/apply`）才写 vault；「放弃」丢掉提案；提案生成后详情又变了（比如另一台电脑已更新）则不能应用，要重新核对；「我已核对，没变化」只记核对日期。还没有详情的会议也能收到提案（第一次建条目），同样在详情页确认。
  - **删除字段：** 提案的 `remove` 列出官网已经没有的旧字段（`dates`、`location`、`homepage`、`cfp_url`、`deadlines`、`tracks`、`notes`、`format.template / review_model / notable_rules`），差异里显示为删除行；覆盖记录里用 `field: null` 表示删除，盖在内置数据上时把那个字段去掉。身份类字段（status、edition、edition_year、sources）不能删。
  - **网址与手改：** `homepage`、`cfp_url`、`sources` 必须能真正解析成 http(s) 网址（`https://<cfp>` 这类会被拒绝），前端取域名时也不会因坏地址崩。覆盖文件可能被手改，所以每条记录读入时都校验：类型不对的整条跳过并在日志里警告，不明字段忽略，`ccfddl_seen` 容错清洗；文件整体读不了就当没有覆盖。新鲜度检查本身出错时，会议库也照常返回（该会议不显示新鲜度）。
  - **覆盖文件：** vault 里的同步安全 YAML（`paths.venue_overrides`，默认在 plan.yaml 旁边的 `venue_details.yaml`），每个会议一条记录，冲突取较新的；`app/venues.py` 把它盖在内置 JSON 上（`format` 按键合并，其余字段整体替换），截稿兜底也用合并后的日期。不写仓库里的 JSON。「恢复内置数据」删除这条覆盖。
  - **内置数据更新后：** 覆盖记录带 `base`（确认时内置数据的届次和核对日期）。之后内置数据换成了更新的一届、或核对日期比你确认的更晚，这条覆盖就算过期：整条不再使用，改用内置数据（不会把旧的赛道、来源和新一届的截稿混在一起），详情页提示「你确认过的更新比内置数据旧」并可清除；在它上面再次确认时从内置数据重新开始。

### 4.6 截稿提醒（10/25 已实现）
- **提醒什么：** `plan.timeline()` 里的三类事件，可以分别关掉：

- **什么时候提醒：** 每个事件在每个提前量各提醒一次，默认 14、7、3、1 天和当天。天数按本地日历日算，截止时刻过了就不再提醒。
  - 每条提醒在那一天的「每天几点提醒」时刻发出，默认 09:00，不会半夜发。
  - 当天那条另外保证在截止前至少 3 小时发出：早上 7 点截止的，凌晨 4 点就提醒。
  - 错过的只补最近的一次。例如 Mac 关了一周，回来时还剩 2 天，只发「还有 2 天」，不会把 14、7、3 天的一起补发。
  - 一次检查要发的超过 4 条时，发最紧的 3 条，再加一条「另有 N 项临近」。
- **不重复：**
  - 会议截止的键是「会议 + 摘要/全文 + 截止日期」，不含显示的标题。官网核实的兜底条目标题带「主会」，ccfddl 公布这一届后标题就变了，但仍是同一个截止，不会重发。同一天截止的几个赛道合成一条。里程碑的键带日期。截止延期或里程碑改期，就重新开始提醒。
  - 发过的记录存在 vault 的 `reminders.yaml`，和 `plan.yaml` 同目录。它是同步安全的 Store，冲突副本会自动合并，两台 Mac 都看得到。本机另记一份在数据目录（`~/Library/Application Support/PhD Studio/reminders.json`，不同步）。两边任一处有记录就不再发，所以重启、同步冲突丢记录、换提醒设备都不会重复。记录在事件过去 30 天后清理。
  - 只有「提醒设备」发通知。设置存在同一个 `reminders.yaml`，两台 Mac 共用；第一次开启时设为本机，可以在设置里改。另一台即使装了后台检查，也只会跳过。
  - Mac 用数据目录里生成的 id（`machine-id`）区分，不用主机名：主机名会随网络变，两台 Mac 也可能同名。主机名只用来显示。
  - 这台不是提醒设备时，设置里那一行和面板顶部都会写明「由 X 发提醒，这台不发」。各设备的「上次在线」也记在 `reminders.yaml` 里，最多 6 小时写一次，设置里能看出提醒设备是不是好几天没检查了。
  - 同一台 Mac 上的检查用文件锁串行，不会两个进程同时发。
- **免打扰：** 可设时段，默认 22:00–08:00，可以跨午夜。
  - 落在时段里的提醒，等时段结束后的第一次检查补发。
  - 如果等到时段结束截止已经过了（例如凌晨 3 点截止），这条提前到时段开始前一小时发。
  - 每小时都检查，所以时段再长（例如 08:30–18:30）也只是推迟，不会丢。
- **工作台关着也提醒：** 后台检查是一个 LaunchAgent（`~/Library/LaunchAgents/local.phd-studio.reminders.plist`），每小时整点和登录时各跑一次 `studio remind --check`，Mac 睡着错过的，醒来后补跑一次。它会改动系统设置，所以只在用户点设置里的「安装到本机」时安装，卸载也在那里，从不自动安装。装好后立刻用 `launchctl kickstart` 跑一次（实测 Background 类任务的 RunAtLoad 会被系统推迟）。
  - 运行方式：找到用本项目构建的 PhD Studio.app（核对启动器里写死的项目路径）时，直接运行 app 自己的可执行文件，用环境变量 `PHD_STUDIO_TASK="remind --check"` 让 `app/desktop.py` 跑检查而不是开窗口（启动器不看命令行参数）。这样进程就是 PhD Studio：沿用 app 读「桌面」文件夹的授权（项目和 vault 都在桌面上，launchd 直接起的 Python 需要自己另外授权；实测 launchd 起的 app 进程读桌面上的项目没有弹授权），通知也以 PhD Studio 的名义发。找不到 app 时退回项目 venv 的 Python（`.venv/bin/python -m app.cli remind --check`），从不用 `sys.executable`（在 app 里那是启动器本身）。
  - plist 不带安装时所在进程的任何环境变量。只有用项目自己的 `studio.toml` 运行的工作台才能安装；用 `STUDIO_CONFIG` 指向沙箱或测试的工作台不行，否则全局只有一个的后台检查会被改指到那份配置。plist 和现在应有的内容（程序、环境、间隔）不一致时，设置里提示重新安装。
  - 运行状况：检查每次运行（包括出错）都把结果写进数据目录；设置还会读 launchd 的运行次数和上次退出码。所以「后台检查」显示的是实际状况：正常、出错（附原因或退出码）、等待检查，或者「停了」（超过 3 小时没检查）。venv 方式在桌面上被 macOS 隐私保护挡住时，会显示为出错，并提示改用 PhD Studio.app。
  - 日志：app 方式写在 `~/Library/Logs/PhD Studio.log`，venv 方式写在 `PhD Studio Reminders.log`。
- **怎么发通知（未签名的本地 app）：**
  - `UNUserNotificationCenter`：需要进程属于一个 app bundle。实测 ad-hoc 签名的 app 可以用：通知显示 app 的名字和图标，点击能回到窗口。两个限制：
    - app 要放在正常位置（桌面、应用程序）。放在临时目录时，通知服务认不出它（`usernoted: Failed to find or validate client`），授权请求直接返回「Notifications are not allowed for this application」。
    - 授权只由「发一条测试通知」请求，因为请求时窗口一直开着，用户可以回答。实测后台检查发出的授权请求没人回答、进程退出后，系统记成了「拒绝」。所以后台检查遇到「还没授权」时不发、不记，留到下次，设置里提示先点测试按钮。被拒绝时设置里有「打开通知设置」按钮。
    - 开着专注模式时不弹横幅，通知直接进通知中心，授权提示也一样。裸 Python 进程里调用会直接抛 NSException 让整个进程退出，所以只在主 bundle 是 PhD Studio 时才碰它。PyObjC 没装 UserNotifications 绑定，框架按路径加载，回调 block 的类型手动注册，不需要新依赖。
  - `osascript display notification`：任何进程都能用，但通知显示为「脚本编辑器」，点了打开的是脚本编辑器，不能跳回工作台。只在不是从 PhD Studio.app 运行时（`start.sh`、直接跑 `studio remind`）退回用它；如果是 PhD Studio 的通知被用户关掉，不会换成脚本编辑器绕过去。
- **点通知跳到事件：** 桌面窗口启动时（在 pywebview 启动之前）设好通知中心的 delegate：窗口在前台时也显示横幅；点击时把窗口调到前面，并在页面里打开对应的会议详情（会议/目标）或「我的规划」（里程碑）。app 没开时，点通知会先启动 app，同一个点击随后送达。
- **接口与命令：** `GET /api/reminders`、`PUT /api/reminders/settings`、`POST /api/reminders/test`、`POST /api/reminders/agent {install}`（`app/reminders_api.py`）。`studio remind`（看接下来的提醒）、`studio remind --check [--dry-run] [--now 2026-11-01T09:00]`、`studio remind --test`。命令行不提供安装。
- **代码：** 排程、去重、文案在 `app/reminders.py`（`due()` / `schedule()` 是纯函数，测试用假时钟）；发通知在 `app/notify.py`；LaunchAgent 在 `app/remind_agent.py`；界面在 `web/reminders.js`。
